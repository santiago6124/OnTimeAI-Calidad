/* "Reducir movimiento": el barrido apaga toda animación y toda transición de
 * la app. Es el default correcto para una interfaz que no fue pensada con esa
 * preferencia en mente, y la mayor parte de esta no lo fue.
 *
 * Pero `!important` sobre los longhands le gana a cualquier `animation:` que
 * escriba un componente, por específico que sea su selector. Eso convierte el
 * barrido en un techo: un componente que SÍ tiene un tratamiento pensado para
 * movimiento reducido —quitar el desplazamiento y dejar la opacidad, en vez de
 * quedarse en una imagen fija— no tiene forma de expresarlo.
 *
 * `data-movimiento-propio` es la salida. El elemento que lo lleva, y todo lo
 * que tiene adentro, queda afuera del barrido y se hace cargo él mismo de la
 * preferencia. No es permiso para ignorarla: es la obligación de atenderla en
 * su propio bloque `prefers-reduced-motion`. Hoy lo usa la cortina de nubes de
 * meteorología, que sin esto era una imagen fija que desaparecía de golpe
 * —exactamente lo que el barrido quería evitar— para quien tiene la
 * preferencia activada. */
@media (prefers-reduced-motion: reduce) {
  *:not([data-movimiento-propio]):not([data-movimiento-propio] *),
  *:not([data-movimiento-propio]):not([data-movimiento-propio] *)::before,
  *:not([data-movimiento-propio]):not([data-movimiento-propio] *)::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
  html {
    scroll-behavior: auto !important;
  }
}

 *
 * En un navegador de escritorio `env(safe-area-inset-*)` vale 0, así que esto
 * es un no-op exacto para la web. Solo tiene efecto en el bundle nativo, donde
 * el viewport es `viewport-fit: cover` y el WebView ocupa la pantalla completa
 * —notch y barra de gestos incluidos—, así que el contenido queda debajo de
 * ellos si nadie lo separa. */
/* CUIDADO: estas dos reglas estan fuera de toda @layer, y las utilidades de
 * Tailwind viven en `@layer utilities`. En la cascada el CSS sin capa le gana a
 * cualquier capa, asi que `.safe-top` le gana a `pt-6`, `p-4` o cualquier otra
 * utilidad de padding vertical puesta en el mismo elemento — y en escritorio
 * `env(safe-area-inset-top)` vale 0, o sea que el espaciado desaparece sin que
 * nada falle ni avise.
 *
 * Por eso no van nunca en el mismo elemento que una utilidad de padding del
 * mismo lado. El patron es un contenedor con la clase de area segura y un hijo
 * con el espaciado: ver `app-nav.tsx` y `app-shell.tsx`, que se armaron asi
 * despues de que la barra apareciera pegada al borde superior. */
.safe-top { padding-top: env(safe-area-inset-top); }
.safe-bottom { padding-bottom: env(safe-area-inset-bottom); }

/* ── Cortina de nubes de /weather ─────────────────────────────────────────
 *
 * La página pide los vuelos del día, arma hasta 150 códigos de aeropuerto y
 * después el METAR de cada uno. Son varios segundos contra una pantalla a
 * medio dibujar, y un esqueleto gris no explica la espera.
 *
 * Las capas derivan a distintas velocidades para dar profundidad; al terminar
 * la carga se abren hacia los costados en vez de desvanecerse, que es lo que
 * hace que se lea como "se despeja" y no como "se apagó".
 *
 * Van sin `@layer` a propósito, como `.safe-top`: las utilidades de Tailwind
 * viven en `@layer utilities` y una regla sin capa les gana, que es lo que
 * hace falta para que el overlay no dependa del orden de clases.
 */
/* La amplitud importa tanto como la velocidad: la capa mide el doble de la
 * pantalla, así que un 12% se traduce en poquísimo movimiento aparente. */
@keyframes deriva-nube {
  from { transform: translate3d(-9%, 0, 0) scale(1.04); }
  to   { transform: translate3d(9%, 0, 0) scale(1.04); }
}
 
/* La entrada: las nubes llegan desde los costados en vez de aparecer puestas.
 * Sin esto el primer segundo es una imagen fija, que es lo que se reportó
 * como "no hay ninguna animación". */
@keyframes entra-nube-izq {
  from { transform: translate3d(-26%, 0, 0) scale(1.04); opacity: 0; }
  to   { transform: translate3d(-9%, 0, 0) scale(1.04); }
}
 
@keyframes entra-nube-der {
  from { transform: translate3d(26%, 0, 0) scale(1.04); opacity: 0; }
  to   { transform: translate3d(9%, 0, 0) scale(1.04); }
}
 
@keyframes respiro-nube {
  0%, 100% { opacity: 0.85; }
  50%      { opacity: 1; }
}
 
/* La entrada de las versiones con movimiento reducido, de las dos cortinas:
 * la misma llegada, sin desplazarse. Aparecer puesta también se lee como "no
 * hay animación". */
@keyframes aparece-cortina {
  from { opacity: 0; }
}
 
/* La deriva tiene que notarse en los pocos segundos que la cortina está a la
 * vista. Con los 58 y 90 segundos de la primera versión el movimiento era de
 * menos del 2% del ancho en cuatro segundos: técnicamente animado, en los
 * hechos una foto. */
.nube {
  animation: var(--entrada) 1.4s cubic-bezier(0.22, 1, 0.36, 1) both,
             deriva-nube var(--velocidad, 16s) ease-in-out 1.4s infinite alternate,
             respiro-nube 9s ease-in-out infinite;
  will-change: transform, opacity;
}
 
/* Al despejar, cada mitad se va para su lado. El `cubic-bezier` arranca lento
 * y acelera: una nube que se abre de golpe parece un telón, no clima. */
.nube-despeja-izq { animation: none; transform: translate3d(-115%, 0, 0); }
.nube-despeja-der { animation: none; transform: translate3d(115%, 0, 0); }
.nube-despeja-izq,
.nube-despeja-der {
  transition: transform 1100ms cubic-bezier(0.45, 0, 0.2, 1),
              opacity 900ms ease-out 200ms;
  opacity: 0;
}
 
/* Con "reducir movimiento" activado no se apaga todo: se quita el
 * DESPLAZAMIENTO, que es lo que molesta a quien tiene sensibilidad vestibular,
 * y se deja el cambio de opacidad, que no.
 *
 * La primera versión ponía `animation: none` y un fundido de 250 ms, y el
 * resultado era una imagen fija que desaparecía de golpe. Eso no es respetar
 * la preferencia, es abandonarla: quien la tiene activada se queda sin saber
 * que la página está cargando, que es justo lo que la cortina viene a
 * resolver.
 *
 * El respiro va más lento que en la versión con movimiento —14 s contra 9—
 * para que se lea como algo vivo y no como un parpadeo. */
@media (prefers-reduced-motion: reduce) {
  .nube {
    /* El respiro arranca después de la entrada: hasta los 900 ms está en
     * retardo y no aporta opacidad, así que no pelean. */
    animation: aparece-cortina 900ms ease-out both,
               respiro-nube 14s ease-in-out 900ms infinite;
  }
  .nube-despeja-izq,
  .nube-despeja-der {
    transform: none;
    transition: opacity 900ms ease-out;
  }
}
 
/* ===========================================================================
 * Cortina de pista — /flights

 * Sin `@layer`, por el mismo motivo que las nubes: tiene que ganarle a las
 * utilidades de Tailwind sin depender del orden de las clases.
 *
 * Todo lo que se anima acá es `transform` u `opacity`, y eso no es un detalle
 * de prolijidad: la cortina está a la vista justo mientras el hilo principal
 * parsea 240 KB de JSON y monta el mapa. Una animación de `background-position`

 * mirando; transform y opacity las resuelve el compositor y siguen corriendo
 * aunque el JavaScript esté ocupado.
 * ======================================================================== */
 
/* El tramo de pista: eje y luces de borde, que se acercan juntos.
